# 프로토타입 환경 설계 (Prototype Environment Design)

- 작성일: 2026-08-19
- 상위 문서: [2026-08-18-ai-investment-copilot-design.md](./2026-08-18-ai-investment-copilot-design.md) (제품 코어 설계 v2)
- 범위: **프로토타입의 지면 구조·진입 경험·평가자 시나리오·안내 레이어.** 제품 코어(프레임 루프, 에이전트 로직, API)는 상위 문서를 따르며 여기서 재정의하지 않는다.

> 이 문서는 "프로토타입 환경" 브레인스토밍에서 확정된 결정의 단일 원본이다.

---

## 1. 해결하는 문제

기존 형상(스크린샷 배경 + FAB → 데스크톱 와이드 에이전트 지면)에는 네 가지 결함이 있었다.

1. **고정 스크린샷 의존** — FAB이 파는 약속("어느 화면에서든 맥락을 알고 온다")을 정적 스크린샷은 증명할 수 없다. 맥락을 하드코딩하는 순간 스스로 금지한 scripted demo가 된다.
2. **정해진 시나리오 냄새** — 씬 선택·시드 주입 방식은 "고를 수 있는 대본"이라, LLM을 붙인 의미(열린 시스템)가 첫 화면에서 죽는다.
3. **발견 가능성 부재** — 평가자는 설명자 없이 혼자 URL을 연다. 열린 시스템의 숙명적 약점("어디부터 만져야 할지 모른다")을 해결해야 한다.
4. **루프가 안 보임** — 코어는 기능 목록이 아니라 루프(형성→대조→기록→회고)인데, 탭 나열(병렬 구조)로는 순차 구조가 전달되지 않는다.

## 2. 설계 원칙

1. **목소리 분리** — 폰 프레임 안 = 순수 제품(데모 스캐폴딩 제로), 프레임 밖 = 도슨트(안내·메타 정보). 물리적으로 분리한다.
2. **맥락은 배경이 아니라 라이브 입력** — 스크린샷에 맥락을 박지 않는다. 맥락이 필요한 화면(종목상세)은 데이터 구동으로 만들고, 평가자가 직접 조작한다.
3. **대본 금지, 안내는 허용** — 시드 문장·고정 씬 없음. 안내는 칩·플레이스홀더·도슨트(제품 밖 목소리)로만 한다.
4. **대화가 루프의 축** — 대화 스레드는 그 자체가 타임라인이라, 루프가 요구하는 순차성을 공짜로 가진 유일한 UI 구조다. 기능은 대화 안으로, 지면은 기억 보관소로.

## 3. 전체 레이아웃

```
┌──────────────────────────────────────────────────┐
│ 배경: 흰색(#fff)                                    │
│                                                  │
│   [폰 프레임]                [도슨트 패널]            │
│   iPhone 16 Pro 비율          ① 여정 체크리스트(자동)  │
│   (402×874pt, 뷰포트에         ② 현재 단계 내레이션    │
│    맞춰 축소, ~9:19.5)         ③ 실동작/목업 투명성 배지 │
│   순수 제품만                   ④ 🔄 데모 초기화        │
└──────────────────────────────────────────────────┘
```

- **폰 프레임**: 최신 아이폰(iPhone 16 Pro) 비율 402×874pt 기준. 뷰포트 높이에 맞춰 비율 유지 축소(`height: min(85vh, 874px)` 수준). 라운드 베젤·노치(다이내믹 아일랜드) 디테일로 실기기 느낌.
- **배경**: 흰색. 프레임과 도슨트 패널 외 장식 없음.
- **모바일 접속 폴백**: 도슨트 패널을 접히는 하단 시트로 전환. 데스크톱 기준 설계 우선.
- 별도 랜딩 페이지 없음 — **도슨트 패널이 곧 랜딩**(첫 화면부터 체크리스트가 보임). `/prd`와 상호 링크.

## 4. 프레임 안: 화면 구조

### 4.1 홈 (진입, 정적)

- **실제 카카오페이증권 홈 스크린샷** 유지. 우리가 얹는 오버레이는 **FAB 딱 하나** — FAB 자체가 제품 제안이므로 이것만이 정당한 오버레이다.
- 스크린샷은 "이 제품은 진짜 저 앱 안에 산다"는 배치 스토리의 앵커. 코드로 다시 그리면 베이스 앱을 왜곡하고 앵커가 약해진다.
- 홈은 맥락을 싣지 않는다(맥락 없는 화면이므로 정적이어도 정직하다).

### 4.2 종목상세 (라이브, 보너스 경로용)

- **데이터 구동 화면 1종**: 검색으로 아무 종목 진입 → 기존 quote/history API로 실시간가·등락·미니차트 렌더. 하단 판매/구매 바 유지(결정 직전이라는 히어로 장면).
- 호가/토론/뉴스 등 나머지 탭은 정적 장식(탭 시 "프로토타입 범위 밖" 안내).
- 검색 진입: 홈 스크린샷 위 핫스팟 1개(실제 앱의 검색 요소 위치) → 라이브 검색 화면 푸시. 실제 앱도 검색은 별도 화면 전환이므로 "스크린샷(홈) → 라이브(검색)" 경계가 자연스러운 전환점과 일치한다.
  - 스크린샷에 검색 요소가 없으면: 종목 리스트 위 핫스팟(→ 해당 종목 라이브 상세) 또는 최후에 헤더 돋보기 아이콘 추가(실앱 스타일 준수). *구현 시 스크린샷 확인 후 결정.*
- **스크린샷 vs 라이브 분담 기준**: 맥락 없는 화면(홈) = 스크린샷, 맥락을 싣는 화면(검색·종목상세) = 라이브.

### 4.3 FAB → 바텀시트 → 풀프레임 미니앱

- FAB 탭 → 현재 화면 위로 **바텀시트**가 올라오며 오프닝 브리핑("화면 위에 얹힌 동반자" 은유를 첫 3초에 시각화) → 끌어올리거나 계속하면 프레임 전체를 덮는 미니앱으로 확장. **에이전트는 어떤 경우에도 프레임 밖으로 나가지 않는다.**
- 닫으면 이전 화면(홈/종목상세)으로 복귀 — 다른 종목으로 이동 후 재호출하면 "따라오는 맥락"이 시연된다.

### 4.4 미니앱: 대화 + 위키 2축

기존 6탭(대화·프레임·결정·회고·위키·커뮤니티)을 2축으로 압축한다.

| 축 | 역할 | 내용 |
|---|---|---|
| **💬 대화** | 루프의 **흐름** | 모든 기능이 일어나는 곳. 프레임 형성·결정 대조·회고가 대화에서 트리거되고, 결과는 **인라인 카드**로 렌더 |
| **🗂 위키** | 루프의 **축적** | 프레임(원칙) + 판단 기록 + 회고 히스토리. 공유 버튼은 목업(커뮤니티 다리) |

- **인라인 카드**: 대조 결과(부합/위반/반대근거), 백테스트 결과가 채팅 안에 컴팩트 카드로 렌더 → 탭하면 전체 화면 상세 뷰로 확장. 기존 DecisionPage/RetroPage/FramePage는 **카드의 상세 뷰로 재활용**(탭 지위에서 강등).
- **기록 칩**: 대조가 끝날 때마다 채팅에 "🗂 위키에 기록됐어요" 칩 → 탭하면 위키의 해당 카드로. 루프의 연결(②→③→④)을 제품 흐름이 스스로 증명한다.
- 채팅을 위로 스크롤하면 루프 1회전이 시간순으로 박제되어 보인다 — 이것이 "루프가 안 보임" 문제의 해답.

### 4.5 상태 적응형 기능 칩 (입력창 위 상시 노출)

에이전트를 호출했을 때 할 수 있는 일을 **제안 칩 메뉴**로 제공하되, 사용자 상태에 따라 구성이 바뀐다.

- **프레임 없음(첫 방문)**: 오프닝 브리핑 = "아직 매매 원칙이 없으시네요. 5분이면 같이 만들 수 있어요" + 칩 **[📋 내 매매 원칙 만들기]**(강조) / [🎯 종목 대조해보기] / [🗂 위키 보기].
  - 대조 칩은 죽은 버튼이 아니다 — 누르면 에이전트가 "원칙이 없으면 일반 팩트 브리핑만 가능해요, 먼저 원칙부터 만들까요?"로 자연 유도.
- **프레임 있음**: 오프닝 브리핑이 프레임 기반으로 분기("'급등 3일 후 진입 금지' 원칙 기준으로 도와드릴게요") + 칩 **[🎯 이 종목 내 프레임에 대조]** / [🔁 과거 검증(회고)] / [📋 원칙 다듬기] / [🗂 위키]. 종목상세에서 열었다면 맥락 상속과 결합.
- 구현: `loadFrame()` 상태를 시스템 프롬프트와 오프닝/칩 구성 분기에 주입.
- 칩은 자유 입력과 항상 공존 — "가이드된 빈 화면" 원칙의 강화판이지 대본이 아니다. 플레이스홀더("예: 삼성전자 지금 사도 될까?")도 유지.
- **기술 필수 요건**: 채팅이 종목 **이름을 알아듣고 코드로 해석**해야 한다(이름→코드 리졸버). 주 경로의 유일한 신규 필수 백엔드 작업.

## 5. 평가자 시나리오

**주 경로 = 대화 우선.** "AI 에이전트"라고 듣고 온 평가자의 본능(에이전트 열고 말 걸기)이 곧 설계된 주 경로다. 안내를 안 읽어도 올바른 경험을 하게 된다.

1. 홈(스크린샷) → **FAB** → 바텀시트 → 미니앱
2. 대화로 **프레임 형성** (상태 칩이 유도)
3. 대화로 **결정 대조** — "에코프로비엠 지금 사도 될까?" → 에이전트가 이름을 해석해 실데이터로 대조 + 반대근거. 검색 화면 불필요, **검색은 에이전트가 대화 안에서 한다.**
4. **회고** 백테스트 되먹임 (인라인 카드)
5. **⭐보너스(도슨트 안내)**: "이번엔 앱을 둘러보다 불러보세요" — 검색→종목상세(라이브)→FAB → 첫마디에 맥락 상속 확인. 화면 맥락 상속은 사이드 퀘스트이며, 평가자가 하지 않아도 코어 루프는 완주된다.

## 6. 프레임 밖: 도슨트 패널

전시회 큐레이터처럼 명백히 "데모 가이드"로 라벨링된 메타 레이어. 제품을 연출하지 않고 관람 순서만 안내하므로 아무리 지시적이어도 제품 정직성을 해치지 않는다.

1. **여정 체크리스트 (자동 체크)** — 5+1스텝: ① FAB으로 Frame 호출 → ② 대화로 내 매매 원칙 만들기 → ③ 아무 종목이나 결정 대조 + 반대근거 → ④ 회고 백테스트 되먹임 → ⑤ 위키에서 쌓인 기록 확인 → ⭐ 종목상세에서 다시 불러보기(맥락이 따라옴). 앱 상태 이벤트로 자동 체크. 체크리스트는 완주를 유도한다.
2. **현재 단계 내레이션** — 지금 단계가 PRD의 어떤 주장을 증명하는지 1~2줄. 와우 모먼트("다른 종목으로 옮겼다 다시 불러보세요")의 등을 밀어준다.
3. **실동작/목업 투명성 배지** — "시세: 토스 API 실호출 · 에이전트: LLM 라이브 · 커뮤니티: 목업". 평가 기준이 '구현 과정'이므로 뭐가 진짜인지 스스로 밝히는 것 자체가 신뢰 점수이며, canned 의심을 원천 차단한다.
4. **🔄 데모 초기화** — 프레임·위키·대화·체크리스트 진행 전부 리셋(확인 모달 1회). 프레임 밖에 두는 것이 원칙("안 = 제품, 밖 = 데모 유틸")에 부합. 초기화하면 "프레임 없던 시절의 에이전트"를 다시 볼 수 있어 상태 적응(4.5)의 전/후 차이를 반복 체험 가능.
- **펄스 하이라이트**: 도슨트 스텝 활성 시에만 프레임 안 해당 요소에 1~2초 임시 펄스 허용(침범이 아니라 포인터).

## 7. 스코프 & 작업 덩어리

| 작업 | 성격 |
|---|---|
| AgentApp 데스크톱 와이드 → 폰 프레임(402×874 비율) 모바일 재배치, 2축(대화+위키) 재구성 | **최대 덩어리** |
| 채팅 인라인 카드(대조/백테스트) + 기존 페이지의 상세 뷰 전환 | 중 |
| 상태 적응 칩 + 오프닝 분기 + 이름→코드 리졸버 | 중 |
| 도슨트 패널(체크리스트·내레이션·배지·초기화) | 중 |
| 바텀시트 오프닝 연출 | 소 |
| 라이브 검색 + 종목상세 1종 (보너스 경로) | 중 — **주 경로와 독립이므로 시간 부족 시 마지막에 자름** |
| 홈 스크린샷 + FAB + 핫스팟, 배경 흰색 | 소 |

- 스코프 가드레일: 종목상세 템플릿 1종만. 라이브 화면의 목업 퀄리티 확장(호가·차트 탭 등) 금지.
- 잘라도 되는 순서(시간 부족 시): 보너스 경로(검색·종목상세) → 펄스 → 바텀시트 연출(즉시 전환으로 대체).

## 8. 이 설계가 닫는 문제 (1장과 대응)

| 문제 | 해답 |
|---|---|
| 고정 스크린샷 의존 | 스크린샷은 맥락 없는 홈에만. 맥락 화면은 라이브(4.2) |
| 정해진 시나리오 냄새 | 대화가 주 인터페이스 = 대본 원천 불가. 씬·시드 없음(5) |
| 발견 가능성 | 평가자 본능 = 주 경로(5) + 상태 칩(4.5) + 도슨트(6) |
| 루프가 안 보임 | 대화 스레드 = 타임라인(4.4), 위키 = 축적, 체크리스트 = 지도 |
