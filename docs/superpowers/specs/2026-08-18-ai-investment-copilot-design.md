# AI 투자 Frame — 설계 문서 (Design Spec) v2

- 작성일: 2026-08-18 (v2: 코어 재정의 — "영상→내 전략" → "나만의 거래 프레임 강화 루프")
- 과제: 카카오페이증권 프로덕트 빌더(시니어) — "AI를 활용해 주식 투자 프로덕트 Prototype 만들기"
- 기한: 안내일로부터 4일
- 산출물: PRD(1~2p) · Prototype(GitHub + URL) · AI 활용 문서
- 평가 기준(중요): **완성도보다 문제 정의 · 문제 해결 방식 · 구현 과정.**

> 이 문서는 브레인스토밍에서 확정된 결정의 단일 원본이다. PRD 딜리버러블과 구현 계획은 이 문서에서 파생한다.

---

## 1. 한 줄 정의

**"나만의 거래 프레임"을 만들고 · 지키고 · 다듬게 돕는 AI 투자 Frame.** 2030 초보·감투자자가 남을 따라 하지 않고, 자기 판단 기준으로 결정하고, 그 판단이 시간이 지날수록 자라게 한다.

## 2. 해결하려는 문제

**뿌리 원인: 자기만의 거래 프레임(판단 기준)이 없다.**

"정보는 넘치는데 판단이 안 된다"를 한 겹 더 파면 두 결핍이 나온다.
- **R1 · 프레임 부재:** 무엇을 근거로 사고팔지 기준이 없다. 매 결정이 즉흥·감정·남의 말. "왜 사?"에 구조적으로 답을 못 한다.
- **R2 · 피드백 루프 부재:** 왜 샀는지 기록이 없어, 결과가 실력인지 운인지 구분 못 한다. 그래서 다음에도 같은 실수 → **판단력이 안 자라는 진짜 이유.**
- **R3 · 감정(FOMO·패닉):** 중요하지만 대개 R1의 하위 증상. **프레임이 생기면 흔들릴 때 돌아갈 기준이 생겨 감정 매매가 크게 준다.**

이 결핍이 실패 패턴(쏠림·추격매수·뇌동매매·손절실패)으로 발현된다. 즉 실패 패턴은 증상, **프레임·피드백 부재가 원인.**

## 3. 타겟 고객

- **2030 초보 투자자 + 감으로 투자하는 사람.** 모바일 네이티브, 유튜브로 학습, 커뮤니티 활발, 소액·잦은 매매.
- 카카오페이증권의 결(쉽고 친근한 UX, 행동 넛지)과 정렬.

## 4. 해결 원칙 (고정)

1. **답을 주지 않는다.** AI는 "사라/팔아라"를 대신 결정하지 않는다. **프레임을 끌어내고 · 대조하고 · 되먹인다.** 판단의 주체는 사용자.
2. **항상 사용자 맥락 근거** — 내 프레임 · 포트폴리오 · 지금 보는 화면.
3. **결정과 외부 발행은 사용자.** 에이전트는 초안까지. 자동매매·자동게시 없음.

> 이 원칙이 앞서 식별한 리스크(AI 안전벨트 착시·책임 전가·검증 안 된 기법에 권위 부여)를 구조적으로 완화한다.

## 5. 에이전트 페르소나

**"팩트로 브리핑하고, 되묻고, 반대편도 보여주는 친근한 투자 선배" = 프레임을 끌어내는 촉진자.**
- 톤: 친근·직설(2030 초보 진입장벽↓).
- 행동: ① 내 맥락 팩트 브리핑 → ② 소크라테스식 되묻기("왜 지금? 네 규칙엔?") → ③ 악마의 변호인(반대 근거).

## 6. 코어: "나만의 거래 프레임" 강화 루프

AI는 답을 주지 않고 프레임을 끌어내고·대조하고·되먹인다. 쓸수록 프레임이 강해지고 판단력이 자란다.

1. **① 프레임 형성** — 대화로 사용자의 원칙(매수/매도 규칙)을 끌어내 저장. 유튜브 기법·본인 경험을 재료로.
2. **② 결정 순간 (히어로)** — 사용자가 입력한 **아무 종목**의 실시간·과거 데이터로 **내 프레임에 대조** + 반대근거. 부합/위반을 짚되 답은 안 준다.
3. **③ 기록** — 그때의 판단 근거를 자동 저장(= 개인 위키). 운/실력 분리의 원천.
4. **④ 회고 = 프레임을 과거에 대입** — 심어둔 일화가 아니라 **내 프레임 × 아무 종목을 실제 과거 데이터에 백테스트-라이트**로 되먹임("네 규칙대로면 여기서 나왔어야"). 즉시·범용·리얼(한계 고지 포함).

## 7. 탐색 가능성 원칙 (프로토타입의 핵심 요건)

프로토타입은 대본(scripted demo)이 아니라 **탐색 가능한 시스템**이어야 한다. 평가자가 아무 종목·프레임·질문으로 벗어나도 동작한다.

- **입력 구동 · 목발 제거:** 고정 영상/데모 포트폴리오/심어둔 결정에 코어를 묶지 않는다. 코어는 LLM 에이전트 + 실데이터라 본질적으로 열려 있다.
- **가이드된 빈 화면:** 입력창 **플레이스홀더를 예시 시나리오**로("예: 삼성전자 지금 사도 될까? / 내 매매 원칙부터 만들래") 길만 안내. 대본은 아님.
- **가드레일:** 페르소나 원칙(답 안 줌)·도구로 사실 접지(환각 방지)·모르면 "모른다/미지원" 정직 처리.
- **시드 데이터 = '예시' 라벨:** 예시 프레임·기록은 지우고 내 걸로 대체 가능.

## 8. 3대 기둥 (재배치)

1. **🧭 Frame(촉진자)** — 프레임을 끌어내고 결정 순간 대조. human-in-the-loop 도구사용 에이전트.
2. **🧠 개인 위키 = 프레임 + 판단 기록 저장소** — 코어로 승격. 프레임과 결정 근거가 축적 → 개인화 + 판단력 성장의 물리적 실체.
3. **👥 커뮤니티 다리** — 프레임·근거 공유 + 멘탈 케어(발행은 사용자 트리거). 라이트.

**유튜브 "영상 → 프레임 재료" 기능** = 와우/온램프로 강등(코어 아님). 아무 영상이나 넣어 기법을 뽑아 **내 프레임의 재료**로 검토(적용이 아니라 재료).

## 9. 진입점 & 아키텍처

- **메인 진입점 — 페이증권 앱 내 플로팅 버튼(FAB) → 바텀시트 Frame.** 어느 화면에서든 한 탭, 부르는 순간 화면 맥락(종목) 인지. 보완: 카톡 채널(로드맵).
- **에이전트:** MVP는 단일 Frame 에이전트 + 내부 도구(시세·과거데이터·백테스트-라이트·프레임/기록 저장). 멀티에이전트는 로드맵.
- **데이터:** MarketData provider 추상화 — **토스증권 오픈 API(주) + Yahoo(무계좌 폴백).**

## 10. MVP 스코프 (4일)

**✅ 실제 동작 (열린 코어)**
- **①프레임 형성** — 대화로 규칙 3~4개 뽑아 저장(사용자 입력 구동)
- **②결정 순간 (히어로)** — 아무 종목 입력 → 실시간/과거 데이터로 내 프레임 대조 + 반대근거
- **③기록** — 판단 근거 자동 저장(위키)
- **④회고** — 내 프레임 × 아무 종목 과거 데이터 백테스트-라이트 되먹임
- 실데이터: 토스(주)/Yahoo(폴백) · LLM: **Claude Sonnet(`claude-sonnet-5`)**

**🟡 라이트 / 목업**
- 개인 위키 UI(프레임·기록 카드 저장·조회) — 라이트 실동작
- 커뮤니티 다리(심리 카드 + 근거 공유 버튼) — 목업
- 유튜브 온램프(영상→프레임 재료) — 시간 되면 실동작, 아니면 데모
- 카톡 채널 · 앱 셸(스크린샷 배경) — UI 목업

**🔮 로드맵 (PRD만)**
- 실계좌/모의 자동주문 · 정식 백테스트 · 커뮤니티 풀 · 코치(감정) 에이전트 · 카톡 실연동 · 멀티에이전트 · 개인화 심화

## 11. 기술 스택 & 산출물

- 프론트: **Next.js**(웹챗, 카톡 스타일, 스크린샷 배경 오버레이) — 배포하여 Prototype URL
- 시세/과거: **토스증권 Open API(주, 실호출 검증 완료) + Yahoo(폴백)**. 카카오페이증권은 외부 개발자용 공개 트레이딩 API가 없어 공개 오픈API로 실데이터 연동.
- LLM: **Claude Sonnet(`claude-sonnet-5`)** — 프레임 끌어내기·대조·되먹임·요약
- 유튜브(온램프): 자막 추출 → LLM으로 프레임 재료화
- 저장소: GitHub `https://github.com/lenell0912/roen-assignment.git`

**보안:** 토스 client_id/secret, ANTHROPIC_API_KEY는 사용자가 `.env.local`에 직접 입력. 코드/문서/커밋에 키 하드코딩 금지.

## 12. 가설 & 검증 지표 (PRD용)

**가설**
- H1. 결정 순간 "내 프레임"에 대조시키면 근거 있는 결정이 늘고 뇌동·추격매수가 준다.
- H2. 판단을 기록하고 결과와 되먹이면(회고) 운/실력이 분리되어 판단력이 자란다.
- H3. 프레임이 생기면 감정 매매(FOMO·패닉)가 준다.

**검증 지표(초안)**
- 북극성(NSM): **"프레임에 근거한 결정 비율"**(프레임 대조를 거친 매매 결정 수 / 전체).
- 활성화: 프레임 형성 완료율, 첫 결정-대조 도달률.
- 판단 품질: 결정 전 프레임 위반 경고 시 **보류/변경률**(뇌동 차단 신호).
- 학습/리텐션: 회고 완료 수, 프레임 업데이트 횟수, 위키 기록 누적, WAU.
- 정성: "혼자보다 나은 결정을 했다 / 내 기준이 생겼다" 인식(설문·NPS).

## 13. 차별화

- 페이증권에 **이미 있는 "증권봇"(Q&A)·"AI인사이트"** 대비 → 우리는 **답을 주는 봇이 아니라, 사용자의 판단 프레임을 키우는 Frame.** (정보 제공 ≠ 판단력 형성)

## 14. 리스크 & 고려사항

- **과신/책임 전가:** "답 안 줌 + 프레임 위반 경고 + 한 번 더 생각 마찰"로 완화. 면책 고지.
- **백테스트 오해(과최적화):** ④는 "정답"이 아니라 "네 규칙을 과거에 비춘 참고"임을 명시, 한계 상시 고지.
- **규제:** 투자자문 아님(보완). 고지 포함.
- **유튜브 자막 미제공:** 온램프는 폴백(설명/수동) 또는 데모로.
- **탐색 중 LLM 오작동:** 가드레일(도구 접지·정직 처리)로 완화.
- **서버리스 배포 시 토스 호출 IP 정책:** 필요 시 Yahoo로 데모.

## 15. 로드맵

- **Phase 1 (4일 MVP):** 열린 프레임 루프(형성→결정→기록→회고) + 토스 실데이터 + Sonnet.
- **Phase 2:** 유튜브 온램프 실동작, 커뮤니티 근거공유 실동작, 정식 백테스트.
- **Phase 3:** 감정 코치 에이전트, 멀티에이전트, 카톡 실연동, 개인화 심화, 모의 자동주문.
